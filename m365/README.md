# Microsoft 365 Copilot scaffold

This folder contains the Microsoft 365 app-manifest starting point for exposing
IT Helper as a **custom engine agent**.

## Why custom engine, not declarative

This sample brings its own:

- orchestrator: Microsoft Agent Framework;
- model: the model deployment in Microsoft Foundry;
- hosted runtime: Foundry Hosted Agent.

Microsoft 365 documentation classifies that shape as a custom engine agent.
A declarative agent is appropriate when Microsoft 365 Copilot owns the
orchestrator and foundation model and the developer adds instructions,
knowledge, and actions.

References:

- [Agents for Microsoft 365 Copilot](https://learn.microsoft.com/microsoft-365/copilot/extensibility/agents-overview)
- [Bring your agents into Microsoft 365 Copilot](https://learn.microsoft.com/microsoft-365/copilot/extensibility/bring-agents-to-copilot)
- [Microsoft 365 Agents SDK .NET quickstart](https://github.com/microsoft/Agents/tree/main/samples/dotnet/quickstart)

## What remains to validate

1. Add Microsoft 365 Agents SDK Activity handling to the hosted agent, or use
   the Activity-protocol scaffold generated by the current Foundry tooling.
2. Add `protocol: activity` to the `it-helper` service in `azure.yaml`.
3. Deploy the agent. Current `azd` guidance says an Activity deployment
   generates `TEAMS_APP_SETUP.md`.
4. Follow that generated file to create/configure the app registration and
   Azure Bot Service channel.
5. Replace `${{AAD_APP_CLIENT_ID}}` and `${{BOT_DOMAIN}}` through Microsoft 365
   Agents Toolkit environment files.
6. Add valid `color.png` (192x192) and `outline.png` (32x32) icons.
7. Package and sideload the app in a licensed development tenant.

This path was not run during the handoff build because a suitable Microsoft
365 tenant was not available. Do not treat the checked-in manifest as a
validated production package.
